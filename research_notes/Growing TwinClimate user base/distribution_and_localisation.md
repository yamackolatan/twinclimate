# Distribution format and localisation for TwinClimate (NL first, then EU), 2025–2026

Research date: 23 Oct 2026. Context: free Flutter app, today only a Flutter web build on GitHub Pages (yamackolatan.github.io/twinclimate), English only. The founder is solo and non-technical, has no computer, works only in a browser, and plans Android/iOS builds through Codemagic.

**Things that need hardware the founder doesn't have (summary flag list):**
1. **Google Play (personal account): a real Android phone is REQUIRED.** New personal accounts must verify access to a physical, non-rooted Android 10+ device with the Play Console mobile app before publishing (sources in section B).
2. **Google Play (personal account): 12 real testers with Android devices for 14 days** before production access.
3. **Apple: no Mac needed to build, sign or upload.** Codemagic does that in the cloud. The founder still can't personally test the iOS build (TestFlight) without an iPhone/iPad. Two-factor authentication on the Apple Account needs at least a trusted phone number. Whether a Dutch individual can enrol fully on the web, or needs the Apple Developer app on an Apple device, was not confirmed (see gaps).
4. **Web / PWA: nothing extra.** Any browser works, and testing needs only a phone (borrowed or friends') for "install" behaviour.

## A. Web vs PWA vs native app-store distribution: growth and retention trade-offs (incl. PWA capabilities and Flutter-web specifics)

### Takeaway
A PWA (the existing Flutter web app made installable) is the cheapest, fastest channel with zero gatekeepers. In 2025–2026 it can be installed on Android/Chrome and on iOS, where since iOS 26 any site added to the Home Screen opens as a web app by default, and it can send push on iOS 16.4+ once installed. It is weak at discovery and SEO, mostly because Flutter web draws to a canvas, and weaker at re-engagement than native. Native store apps add store-search discovery (most store installs start from search) and stronger retention tools, but they bring fees, review, and for Google Play a phone and tester hurdle. The evidence-backed shape is web/PWA now, a separate indexable landing page, then store apps.

### Cited Findings
**PWA installability on Android/Chrome**
- Chrome fires `beforeinstallprompt` (so the app can show its own "Install" button) once minimum installability is met. The criteria: served over HTTPS; a manifest with `short_name` or `name`, 192 px and 512 px icons, and `start_url`; not already installed; the user has clicked or tapped the page at least once and spent at least 30 seconds on it. Other browsers use different criteria. — [web.dev, "What does it take to be installable?"](https://web.dev/articles/install-criteria)
- The Lighthouse installability audit also checks that `display` is fullscreen, standalone or minimal-ui and that `prefer_related_applications` is not true. — [Chrome Developers, Lighthouse installable-manifest](https://developer.chrome.com/docs/lighthouse/pwa/installable-manifest)
- (Codebase check, 23 Oct 2026) `web/manifest.json` already has name/short_name, `start_url: "."`, `display: standalone`, 192/512 and maskable icons, and `prefer_related_applications: false`, so it meets these criteria on HTTPS GitHub Pages. But its `description` still reads "Compare city climates and find your climate twin." and the `index.html` meta description reads "Compare the climates of two cities…". Both are left over from the old city-climate feature, so they are stale copy that search engines and install dialogs show. — local files `/home/user/twinclimate/web/manifest.json`, `/home/user/twinclimate/web/index.html`

**iOS/Safari Home Screen web apps and push**
- iOS/iPadOS 16.4 added Web Push (Push API, Notifications API, Service Workers) **only for web apps added to the Home Screen**. Normal Safari tabs can't ask for push permission. Permission may be requested only after a direct user action such as tapping a subscribe button, and users manage it per web app in Notification Settings. — [WebKit blog, "Web Push for Web Apps on iOS and iPadOS"](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/); [9to5Mac](https://9to5mac.com/2023/02/16/iphone-web-app-new-features-ios-16-4/)
- The Badging API (count on the icon) also works only for Home Screen web apps on iOS 16.4+. It is granted automatically with notification permission. The manifest `id` member is supported. — [WebKit blog, "Badging for Home Screen Web Apps"](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/)
- **iOS 26 / iPadOS 26:** by default every website added to the Home Screen opens as a web app, even without manifest markup. An "Open as web app" switch in the dialog (on by default) can turn this off. Apple says existing web-app support is not removed. — [Michael Tsai blog quoting WebKit](https://mjtsai.com/blog/?p=49472); [heise](https://heise.de/-10749652); [Gigazine on Safari 26](https://gigazine.net/gsc_news/en/20250623-safari-26-webkit-beta)
- Installing on iOS is still a manual Share → "Add to Home Screen" flow. Safari has no programmatic install prompt (no `beforeinstallprompt`). — implied by the WebKit/heise sources above, which describe only the Add to Home Screen dialog; see gaps.

**EU DMA situation**
- Feb 2024: Apple said iOS 17.4 would remove Home Screen web apps in the EU, citing DMA rules on alternative browser engines. 1 Mar 2024: Apple reversed this and kept the existing capability in the EU, still built on WebKit. Pressure came from an Open Web Advocacy open letter and an EU regulator inquiry. Web apps installed from third-party browsers may not get their own engine. — [Notificare](https://notificare.com/blog/2024/03/08/apple-reverse-decision-to-remove-pwa/); [Tom's Guide](https://tomsguide.com/phones/iphones/apples-backtracking-on-plans-to-kill-iphone-home-screen-web-apps-in-the-eu-heres-why); [AlternativeTo](https://alternativeto.net/news/2024/3/apple-reverses-decision-to-remove-progressive-web-apps-from-ios-17-4-in-eu)
- Net for NL/EU users in 2026: Home Screen web apps and iOS web push work in the EU as elsewhere (inferred from the reversal plus the iOS 26 behaviour above; no 2026 EU-specific restriction found).

**PWA vs native: growth and retention evidence**
- I found no rigorous 2025–2026 dataset comparing PWA and native retention. Most claims, such as "Starbucks doubled DAU" or "76% higher conversion", come from vendor blogs without methodology. — [systemsarchitect.net (vendor claim, discount)](https://systemsarchitect.net/?p=12); [MobiLoud PWA vs native](https://www.mobiloud.com/blog/progressive-web-apps-vs-native-apps)
- Qualitative consensus: PWAs lower install friction and widen reach. Native apps have stronger re-engagement loops (push, badges, home-screen presence) and store visibility. Quote: "if your priority is getting to market fast and reaching the widest possible audience, a PWA makes sense as a starting point. If you're focused on customer retention… a native app is hard to beat." — [MobiLoud](https://www.mobiloud.com/blog/progressive-web-apps-vs-native-apps); [Indie Hackers, 6-month PWA vs native party game](https://www.indiehackers.com/post/pwa-vs-native-app-for-a-party-game-what-6-months-of-data-say-about-retention-da126462bb)
- Small usability study (AliExpress): about 57% preferred the native app and about 43% the PWA ("no download or installation"). Not a retention study. — [Theseus thesis](https://www.theseus.fi/handle/10024/863606)
- "Consumers spend 90% of mobile time in native apps" is widely repeated, but the vendor source gives no origin, so treat it as unverified. — [MobiLoud](https://www.mobiloud.com/blog/progressive-web-apps-vs-native-apps)

**Flutter web specifics (load size, renderers, SEO)**
- A default `flutter build web` uses the CanvasKit renderer. The `--wasm` build uses Skwasm when the browser supports WasmGC and falls back to CanvasKit. — [Flutter docs, web renderers](https://docs.flutter.dev/platform-integration/web/renderers)
- CanvasKit adds about 1.5 MB, and widgets can't show until CanvasKit and main.dart.js have both downloaded. Flutter's blog gives load-speed best practices and says Wasm reduces size. — [Flutter blog, optimizing web loading speed](https://flutter.dev/blog/best-practices-for-optimizing-flutter-web-loading-speed); an older post said about 2 MB extra — [Flutter blog, web stable milestone](https://flutter.dev/blog/flutter-web-support-hits-the-stable-milestone). A third-party claim of 8 MB+ initial payloads is unverified. — [DEV Community](https://dev.to/samuelkchris/optimizing-flutter-webs-initial-load-time-an-updated-comprehensive-guide-4j84)
- HTML renderer status conflicts. A 2026 third-party guide says it was removed from stable and Wasm is the default. Older official pages still describe it. The current official docs list only CanvasKit and Skwasm. — [The Flutter Kit 2026](https://theflutterk.it.com/blog/flutter-web-2026-production-ready) vs [Flutter docs](https://docs.flutter.dev/platform-integration/web/renderers)
- SEO weakness: a Flutter web page is essentially a `<canvas>`. Readable DOM nodes appear only once the accessibility/semantics tree is enabled. Workarounds are prerendering each route in headless Chrome (`flutter_prerender`) or mirroring the widget tree as semantic HTML (`esen_seo`, which can't see custom-painted content). — [pub.dev flutter_prerender](https://pub.dev/packages/flutter_prerender); [pub.dev esen_seo](https://pub.dev/packages/esen_seo)
- Ecosystem advice in 2026: Flutter web is "the wrong tool" for SEO/marketing pages. Use a hybrid, with Flutter for the app and a separate plain-HTML/static site for landing pages. — [The Flutter Kit 2026](https://theflutterk.it.com/blog/flutter-web-2026-production-ready); [GeekyAnts, SEO in Flutter web](https://geekyants.com/blog/boosting-seo-in-flutter-web-apps-a-guide-for-limited-pages); [Walturn](https://www.walturn.com/insights/flutter-web-areas-where-it-can-improve)

### Inferences
- The PWA path is nearly free for TwinClimate: the manifest already qualifies. Adding a visible "Install app" button (Chrome `beforeinstallprompt`) and an iOS "Share → Add to Home Screen" hint costs little and turns web visitors into home-screen users. Web push is the only re-engagement tool on the web. On iOS it needs install first, then a tap-to-subscribe. A server to send pushes would be needed, which conflicts with the "no backend yet" rule, so push is a later step.
- Plain web/PWA can't give TwinClimate reliable background tasks such as a scheduled "evening before" reminder computed on the device, home-screen widgets, or background location. Those were not verified in sources this session, and the packing reminder F5 is cancelled anyway. Native also wins on store discovery (section B).
- A separate static landing page (HTML, indexable, ideally on a custom domain, section C) is close to mandatory for SEO. The Flutter app itself will barely rank for searches like "wat trek ik aan hardlopen" or "what to wear running 10 degrees". That landing page can also host the privacy policy and support link both stores require.
- Recommended sequence: (1) fix the stale manifest and meta description, add install prompts, build a landing page plus domain; (2) Android via Google Play, once the phone/tester hurdles are solved, or an organisation account; (3) iOS. iOS users in NL can already use the PWA, and iOS 26 makes Add to Home Screen behave like an app.

### Gaps
- No primary 2025–2026 retention numbers comparing PWA and native were found, only vendor claims.
- I couldn't fetch web.dev/webkit.org/docs.flutter.dev directly (DNS failures in this environment). Findings rely on search snippets of those pages.
- Not verified this session: Android web push without install (I believe Chrome on Android allows it from a normal tab), Flutter's current default service-worker behaviour, and the exact current state of PWA background sync/periodic sync and widgets on each platform.
- Flutter web bundle size for TwinClimate specifically was not measured.

## B. Publishing to Google Play and the Apple App Store from the cloud: discoverability, ASO, costs, rules, review, Mac/phone needs

### Takeaway
Store search is the main way people find apps (about 65% of App Store downloads follow a search, per Apple-attributed figures). iOS publishing is feasible without a Mac through Codemagic: 500 free macOS M2 minutes per month, and automatic signing through an App Store Connect API key. It costs USD 99/year, shown in local currency at enrolment, and most reviews finish within 24–48 h. Google Play costs USD 25 once, but a new personal account must verify a physical Android phone and run a 12-tester, 14-day closed test before going public. Those are the real blockers for a founder with no device. An organisation account avoids the tester rule but needs a legal entity and a D-U-N-S number.

### Cited Findings
**Discovery and ASO**
- About 65% of App Store downloads happen directly after a search (Apple-attributed, repeated by ASO vendors). Some trackers say 65–70%. Google Play search-driven installs are estimated at 50–60%. — [Webtonic ASO statistics 2026](https://www.webtonic.io/blog/app-store-optimization-statistics); [AppDrift ASO stats](https://appdrift.co/aso-statistics)
- In 2026 Apple added search-ad placements further down App Store results, which can take installs from organic listings. App Store Connect's "App Store search" source includes ad installs. — [eMarketer](https://www.emarketer.com/content/apple-widens-app-store-search-ads-capture-high-intent-demand); [Webtonic](https://www.webtonic.io/blog/app-store-optimization-statistics-86c8f)
- ASO vendor guidance for NL: Dutch users are "highly English-proficient but still prefer Dutch-language listings for trust" (vendor opinion, no data). — [AppDrift NL Weather category](https://appdrift.co/app-store-optimization/netherlands/weather)

**Google Play account, costs and testing rule**
- New **personal** developer accounts must run a **closed test with at least 12 opted-in testers for at least the last 14 days continuously** before they can apply for production access in the Dashboard. Production and pre-registration stay disabled until then. This applies to personal accounts created after 13 Nov 2023. Organisation accounts are exempt. — [Google Play Console Help 14151465](https://support.google.com/googleplay/android-developer/answer/14151465); [Choicely summary](https://www.choicely.com/blog/google-play-12-tester-rule)
- The minimum dropped from **20 to 12 testers on about 11 Dec 2024**, with no formal announcement; Play Console wording changed. The 14-day window is unchanged. If opted-in testers drop below 12, the clock resets. — [Adalo forum](https://forum.adalo.com/t/google-play-policy-update-how-anyone-can-get-12-free-testers/53705); [ExtendsClass 2026 guide](https://extendsclass.com/blog/google-plays-closed-testing-requirement-what-developers-need-to-know-in-2026). Some guides say testers must use the app daily. Google's text says "opted-in", so this is unconfirmed. — [Level Up Coding, "12-tester tax"](https://levelup.gitconnected.com/the-12-tester-tax-google-plays-closed-testing-rule-is-quietly-killing-solo-devs-2cea83c2e338)
- **PHONE REQUIRED:** "developers with new personal accounts will be required to verify that they have access to a real Android mobile device using the Play Console mobile app before they can make their app available on Google Play". The device can be any non-rooted physical Android phone running Android 10+. You scan a QR code from the web Console, install the app, select the account and tap Verify. — [Play Console Help 14316361](https://support.google.com/googleplay/android-developer/answer/14316361); [Play Console Help 10841920](https://support.google.com/googleplay/android-developer/answer/10841920)
- Google Play registration fee: USD 25 one-time (standard figure; not re-fetched this session, see gaps).
- **Android developer verification (sideloading too), 2026–2027:** Google is requiring developer identity verification for apps installed on certified Android devices by any route, including sideloading. It opened to all developers in March 2026 and is enforced from 30 Sep 2026 in Brazil, Indonesia, Singapore and Thailand, with global expansion "in 2027 and beyond". A free "limited distribution" account for students and hobbyists (up to 20 devices, no ID, no fee) launches globally around Aug 2026. — [Android Developers Blog, Mar 2026](https://android-developers.googleblog.com/2026/03/android-developer-verification-rolling-out-to-all-developers.html); [Android Developers Blog, Jun 2026](https://android-developers.googleblog.com/2026/06/android-developer-verification.html); [Help Net Security](https://www.helpnetsecurity.com/2026/06/19/android-developer-verification-rollout-markets/); [9to5Google](https://9to5google.com/2025/08/25/android-apps-developer-verification/)
- **Data safety form:** every Play app must complete the Data safety section (what data is collected, why, whether shared). Apps and updates aren't published without it (enforced since 20 Jul 2022). — [Privacy World](https://www.privacyworld.blog/2022/05/google-to-require-apps-to-display-data-safety-information-by-july-20-2022/); [OneTrust comparison](https://onetrust.com/blog/google-data-safety-vs-apple-nutrition-label/)

**Apple account, costs, review**
- Fee: "The Apple Developer Program is 99 USD per membership year. Prices may vary by region and are listed in local currency during the enrollment process." Fee waivers exist only for nonprofits, accredited education and government. — [Apple, Enroll](https://developer.apple.com/programs/enroll/)
- Individual enrolment: an Apple Account with **two-factor authentication**, legal age, and your legal name (no alias or company name), and the seller name shown on the store is your legal name. Organisation enrolment: a legal entity (no DBAs or trade names), a **D-U-N-S number**, a public website, and work email/phone. — [Apple, Enroll](https://developer.apple.com/programs/enroll/)
- Individuals don't need a D-U-N-S number. Dun & Bradstreet issues one free for organisations, with up to about 5 business days quoted. — [Apple D-U-N-S help](https://developer.apple.com/support/D-U-N-S/); [Prompt Engage guide](https://prompt-engage.helpscoutdocs.com/article/2295-apple-developer-enrollment-d-u-n-s-number)
- App Review: "typically reviewing at least 50% of submissions in less than 24 hours and 90% in less than 48 hours". Expedited review is available for critical bugs or events. Every app needs a support link and a privacy-policy link. The privacy policy must state the data collected, how, all uses, third-party protection, and retention, deletion and consent revocation. Apps that access user data (TwinClimate uses location search, not GPS, but check) need purpose strings. — [Apple, App Review](https://developer.apple.com/distribute/app-review/)
- App Store privacy "nutrition labels" are self-declared in App Store Connect, including the practices of third-party SDKs. — [OneTrust](https://onetrust.com/blog/google-data-safety-vs-apple-nutrition-label/)

**Cloud build and signing (Codemagic): no Mac needed**
- Codemagic can sign iOS apps automatically through the App Store Connect API. It selects or generates certificates and provisioning profiles. The API key needs the Developer role for signing and **App Manager** for publishing. The .p8 key file can be downloaded only once. — [Codemagic docs, iOS code signing](https://docs.codemagic.io/flutter-code-signing/ios-code-signing/); [Codemagic blog, signing without a Mac](https://blog.codemagic.io/automatic-code-signing-for-ios-that-doesnt-require-a-mac/)
- Publishing needs an app record created in App Store Connect first, which is done on the website. Codemagic "recommends" uploading the very first version manually. — [Codemagic docs, App Store Connect publishing](https://docs.codemagic.io/flutter-publishing/publishing-to-app-store/); [codemagic.yaml publishing](https://docs.codemagic.io/yaml-publishing/app-store-connect/)
- Owning a Mac "isn't mandatory at all" with Codemagic, though debugging is harder. — [Miquido](https://miquido.com/blog/develop-distribute-ios-flutter-app-no-mac); [Flutter Community/Medium](https://medium.com/flutter-community/how-to-sign-flutter-apps-for-ios-automatically-without-a-mac-a2dc9cfa5a6c)
- Pricing: the free personal plan has **500 macOS M2 build minutes/month** (resets monthly), 1 concurrent build and 30 days of history, with no free Linux/Windows minutes. Overage is USD 0.095/min. Teams don't get free minutes. — [Codemagic docs, pricing](https://docs.codemagic.io/billing/pricing/); [codemagic.io/pricing](https://codemagic.io/pricing)

### Inferences
- **Realistic Android route for this founder:** (a) borrow or buy a cheap Android 10+ phone, since it is needed once for device verification and is also useful for testing; (b) recruit 12 testers from Dutch running/cycling clubs, Strava clubs, or friends, which also produces the first real users and reviews. Paid "12 testers" services on Fiverr exist, but they risk a policy issue and add no real users. Or (c) set up a legal entity (e.g. a Dutch eenmanszaak, which may not count as a separate legal entity; a BV would) to get an organisation account and skip the tester rule. That needs D-U-N-S and paperwork, so it is likely overkill for a demo. Option (b) doubles as user acquisition.
- **Realistic iOS route:** Apple Developer (USD 99/yr, shown in EUR at checkout), Codemagic free tier, all in the browser. The first manual upload Codemagic "recommends" would normally use Transporter/Xcode on a Mac, but Codemagic's App Store Connect publishing can upload builds itself. The founder should ask Codemagic support or just try an automated first upload. Without an iPhone he can't check the app before Apple review, so a friend with an iPhone on TestFlight is the practical substitute.
- Store listings can be localised (title, subtitle, keywords, screenshots) separately from the app's own text. Localising the NL listing into Dutch is a cheap first ASO step, even before the app UI is translated.
- Both stores need a hosted privacy policy and a support URL, which the landing page (sections A and C) can provide.
- The Android sideloading-verification change mainly affects apps distributed outside Play. A Play-published app is handled within Play Console verification, so it is not a blocker if TwinClimate ships via Play.

### Gaps
- I couldn't fetch Google's help pages directly (DNS failure). The 12-tester and device rules come from search snippets of the Google help pages plus secondary sources. Google could have changed them after the snippets were indexed. Re-check in Play Console when creating the account.
- The Google Play USD 25 fee and the D-U-N-S requirement for Play organisation accounts were not re-verified this session.
- Not confirmed: whether a Dutch individual can complete Apple enrolment entirely on the web or needs the Apple Developer app on an iPhone/iPad/Mac (Apple's page links to app-based enrolment and also has a web "Start your enrollment" button). Also not confirmed: whether two-factor setup is possible without an Apple device.
- No NL-specific split of store search vs other discovery channels was found.

## C. Custom domain vs github.io: trust, SEO, partnerships, cost

### Takeaway
A custom domain costs roughly USD 8–14 per year for .app. It works with the current GitHub Pages setup, including free HTTPS. It is worth getting before store listings, partner outreach and a landing page, because the domain then carries the brand, the privacy/support URLs and any SEO value, which a github.io subdomain tied to a personal username does not.

### Cited Findings
- GitHub Pages supports custom domains with free HTTPS through Let's Encrypt. GitHub runs a DNS check and requests a certificate automatically. HTTPS can take up to about an hour after configuration. Wildcard DNS records are discouraged. — [GitHub Docs, securing Pages with HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https); [GitHub blog](https://github.blog/news-insights/product-news/github-pages-custom-domains-https/); [GitHub Docs, troubleshooting custom domains](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/troubleshooting-custom-domains-and-github-pages)
- .app (registry: Google; wholesale rose to USD 14/yr in Aug 2024): Cloudflare Registrar sells at wholesale, about USD 14.20/yr to renew. One tracker shows USD 8.20 for the first year. The market average is about USD 19.97. — [domainoffer.net](https://domainoffer.net/tld/app/cloudflare); [costgoat](https://costgoat.com/compare/domains/app); [Cloudflare blog on at-cost registrar](https://blog.cloudflare.com/cloudflare-registrar/)

### Inferences
- A .nl domain signals "local" to Dutch users and a .app domain signals "app". Price is small either way. Owning both (one redirecting) is cheap insurance against a squatter. The username-based github.io URL also exposes the founder's personal handle and looks unfinished to brand partners such as Decathlon in the demo pitch.
- Getting the domain first means every link shared now (Strava clubs, store listings, partner decks) keeps working if hosting later moves off GitHub Pages.

### Gaps
- No .nl price was found this session (SIDN sets the wholesale price, and registrars vary). No study quantifying the trust/conversion lift of a custom domain over a subdomain was found.

## D. Localisation priorities (NL proficiency, preference for native language, measured impact, next EU languages, Flutter effort)

### Takeaway
The Netherlands has the world's best non-native English (EF EPI 2025 #1), so English-only is less of a barrier there than anywhere else. Survey data still shows most consumers prefer their own language (CSA: 76%, with 40% never buying in another language), and Dutch store listings help trust. Order of priority: a Dutch store listing and landing page first (cheap), Dutch UI second, then German, the largest EU athlete market, with high but not universal English. French, Spanish and Italian matter more because English proficiency is much lower there. Flutter's built-in gen-l10n/ARB system makes the mechanics routine. The real work in TwinClimate is moving about 700 hard-coded English strings, many of them generated sentences, into translation files.

### Cited Findings
- **EF EPI 2025** (published Nov 2025; 2.2 million test-takers in 2024; 123 countries): Netherlands #1 (score 624, "very high"), followed by Croatia, Austria, Germany (top 5 for the first time) and Norway. The Dutch score has fallen every year since 2021. — [EF EPI 2025](https://www.ef.edu/epi/); [IamExpat](https://www.iamexpat.nl/education/education-news/the-dutch-are-best-non-native-english-speakers-world-again); [Wikipedia, EF EPI](https://en.wikipedia.org/wiki/EF_English_Proficiency_Index)
- EF EPI 2025 fact sheets: Belgium #9 (608), France #38 (539), Italy #59 (513); global average 488. — [EF France fact sheet](https://www.ef.com/assetscdn/WIBIwq6RdJvcD9bc8RMd/cefcom-epi-site/fact-sheets/2025/ef-epi-fact-sheet-france-french.pdf); [EF Belgium fact sheet](https://www.ef.com/assetscdn/WIBIwq6RdJvcD9bc8RMd/cefcom-epi-site/fact-sheets/2025/ef-epi-fact-sheet-belgium-french.pdf); [EF Italy fact sheet](https://www.ef.com/assetscdn/WIBIwq6RdJvcD9bc8RMd/cefcom-epi-site/fact-sheets/2025/ef-epi-fact-sheet-italy-english.pdf)
- **CSA Research "Can't Read, Won't Buy – B2C" (July 2020; 8,709 consumers, 29 countries):** 76% prefer to buy products with information in their own language, 40% never buy from websites in other languages, 67% tolerate mixed-language sites, and 73% want reviews in their own language. Germany has the highest share who buy only on local-language sites (57%). CSA: companies that don't localise risk losing "40% or more" of the addressable market. — [CSA Research press release](https://csa-research.com/blogs-events/csa-in-the-media/press-releases/consumers-prefer-their-own-language); [tcworld](https://www.tcworld.info/news/cant-read-wont-buy-1061)
- **Measured impact on app downloads:** Distimo (2012, about 200 iPhone apps that added a native language): downloads +128% in the first week after localising, revenue +26%. On iPad, downloads were flat and revenue +5%. This is an old, iOS-only, short-window study, so treat it as an upper bound. — [OneSky summary of Distimo](https://www.oneskyapp.com/blog/localization-increases-downloads-by-128-on-average-for-iphone-apps/); [WN Hub](https://wnhub.io/news/localization/item-5755)
- AppTweak calls localisation "a powerful growth lever" for downloads, revenue and retention, without a specific current figure. — [AppTweak localization guide](https://www.apptweak.com/en/aso-blog/guide-to-app-store-localization)
- Dutch-specific: vendor ASO guides say Dutch users are fluent but prefer Dutch listings for trust. No survey percentage was found. — [AppDrift NL](https://appdrift.co/app-store-optimization/netherlands/weather); [TechBullion](https://techbullion.com/building-successful-apps-for-the-dutch-market-tips-and-strategies/)

## E. Units and conventions for EU (metric, 24-hour time)

### Takeaway
TwinClimate already uses °C, km, km/h and 24-hour times (e.g. "07:00–10:30"), matching NL/EU conventions. The remaining convention issues come with localisation: date formats and names, and the decimal comma.

### Cited Findings
- (Codebase check) The app writes times as "07:00", temperatures in °C, distances in km, pace in sec/km and wind in km/h (per CLAUDE.md F1–F3 specs and `lib/models/session.dart`). Dates use a hand-built "Sat 24 Oct" English format. — `/home/user/twinclimate/CLAUDE.md`, `/home/user/twinclimate/lib/models/session.dart`
- Flutter's `intl` package (part of the standard i18n setup) provides locale-aware date and number formatting. — [Flutter docs, internationalization](https://docs.flutter.dev/ui/internationalization)

### Inferences

An optional Beaufort or m/s display is a nice-to-have, not a requirement (not sourced; general knowledge).
- UK/Irish users may want miles. That is outside the NL-first scope and only a later toggle.

## F. Accessibility: app-store expectations and the European Accessibility Act (from 28 June 2025)

### Takeaway
The EAA likely doesn't legally apply to TwinClimate today, for two separate reasons. It covers listed service types only (e-commerce, banking, e-books, telecoms, audiovisual media access, passenger transport), and TwinClimate sells nothing itself since its shop links just open decathlon.nl. On top of that, **microenterprises providing services** (fewer than 10 staff and ≤ €2 M turnover/balance sheet) are exempt from the service accessibility requirements. Basic accessibility is still worth doing: it helps users and partners, and the semantics work also helps Flutter web's SEO problem.

### Cited Findings
- EAA (Directive (EU) 2019/882) applies to services provided to consumers after **28 June 2025**. Transitional rules allow some existing contracts and products to continue, up to 28 June 2030 in some cases. — [iubenda EAA guide](https://www.iubenda.com/en/help/179096-eaa-compliance); [accessible.org](https://accessible.org/does-eaa-apply-existing-services/)
- Services covered (Commission "Products and services covered" list): electronic communications/telephony, access to audiovisual media services, elements of passenger transport services, consumer banking, e-books, and **e-commerce**. — [European Commission, EAA (language versions)](https://commission.europa.eu/strategy-and-policy/policies/justice-and-fundamental-rights/disability/european-accessibility-act-eaa_es); [Complianz](https://complianz.io/definition/what-is-the-european-accessibility-act/)
- Article 4(5): "microenterprises providing services shall be exempted from complying with the accessibility requirements referred to in paragraph 3 of this Article and any obligations relating to the compliance with those requirements". Article 4(6) asks member states to give microenterprises guidelines and tools. — [legislation.gov.uk copy of Directive 2019/882, Art. 4](https://www.legislation.gov.uk/eudr/2019/882/article/4)
- Microenterprise = fewer than 10 employees and annual turnover or balance sheet total ≤ €2 million. Voluntary compliance is encouraged. — [Complianz](https://complianz.io/definition/what-is-the-european-accessibility-act/); [RaftLabs](https://www.raftlabs.com/blog/european-accessibility-act-guide)
- Sources disagree on how often software businesses qualify for the exemption. One vendor says "most software businesses don't qualify", while others say microenterprises are not affected "in principle". A solo founder clearly sits under the thresholds. — [accessible.org top-10 EAA questions](https://accessible.org/top-10-eaa-questions/); [iubenda](https://www.iubenda.com/en/help/179096-eaa-compliance)
- Flutter web content becomes readable DOM (for screen readers and crawlers) only when the semantics tree is enabled. Custom-painted content is invisible to it unless labelled. — [pub.dev esen_seo](https://pub.dev/packages/esen_seo); [pub.dev flutter_prerender](https://pub.dev/packages/flutter_prerender)
- (Codebase check) There are no explicit `Semantics(...)` widgets in `lib/`. The app relies on the default semantics of Material widgets. — `/home/user/twinclimate/lib/`

### Inferences
- **EAA scope for TwinClimate:** it's a free information/advice app with outbound links. No contract is concluded in the app, so it isn't "e-commerce" in the EAA sense, and the founder is a microenterprise in any case. If TwinClimate later takes real orders or payments in-app with an entity of 10+ staff or more than €2 M turnover, this needs another look. The Dutch national transposition law was not checked.
- **App stores:** neither store makes a legal accessibility audit a listing condition, as far as found. Apple (App Store Connect "Accessibility Nutrition Labels", announced 2025) and Google review expectations push towards labelled buttons, sufficient contrast, scalable text and screen-reader support (not sourced this session, see gaps). Cheap wins in Flutter: `Semantics`/`tooltip` labels on icon-only buttons (person icon, menu), not encoding rain/wind highlights by colour only, respecting system text scale, and contrast in light and dark mode.
